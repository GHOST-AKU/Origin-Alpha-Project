# Origin Alpha Project 创作工作室使用说明

> 这是使用说明，不是世界观，也不是必须填完的表格。

Origin Alpha Project 尚未确定总体母题、媒介关系和第一阶段交付物。现有结构的任务是保护创作过程，而不是提前规定作品必须长成什么样子。

```text
捕捉 → 生长 → 确认归属 → 需要时才固定
```

## 1. 放在哪里

| 手上的内容 | 位置 |
|---|---|
| 一句对白、一个画面、未分类念头 | `00_inbox/` |
| 尚未成为正典的总体方向或跨作品探索 | `01_project/` |
| 已经确认、并在多个作品中成立的事实 | `02_canon/` |
| 一部具体作品及其全部局部资料 | `03_works/OAP-W###/` |
| 可被多个作品使用的共享研究 | `04_research/` |
| 项目级、跨作品的探索或稳定图表 | `05_boards/` |
| 服务于笔记的轻量附件 | `06_attachments/` |

如果仍然无法判断，先放进 `00_inbox/`。它是合法入口，不是分类失败区。

## 2. 开始一部作品

1. 确认这是一部需要长期引用的真实作品。
2. 分配作品 ID，例如 `OAP-W001`。
3. 确认它实际需要的媒介、内容区和目录形式，不从虚拟骨架开始。
4. 从 `03_works/` 对应内容区的就地模板起步。
5. 替换占位 ID 和标题，再开始创作。

作品专属的人物、地点、时间线、研究、图表和视觉探索都留在作品目录内。不要为同一对象在顶层再建一份“总档案”。

## 3. 什么时候进入正典

`02_canon/` 是确认后的跨作品资料柜，不是世界观草稿箱。内容进入前必须满足：

1. 已经由用户明确确认。
2. 会被多个作品共同引用。
3. 已检查与现有正典的冲突。
4. front matter 使用 `canon_status: canonical`。

尚未确认的跨作品探索放在 `01_project/`；只属于一部作品的设定留在该作品内。

## 4. ID 与状态

ID 只给会被长期引用的对象。灵感便签、临时截图和一次性草稿不强制编号。已分配的 ID 不因改名而变化，也不重复使用。

`status` 只表示生产阶段：

```text
inbox → outline → draft → review → released
```

`archived` 表示不再活跃，`deprecated` 表示已被新对象取代。

`canon_status` 只表示正典身份：

```text
unconfirmed / canonical / non-canon
```

不得再使用 `status: canonical` 或 `status: non-canon`。

## 5. 图表、附件与公共素材

- Canvas、拼贴和草图可以保留矛盾与问号，不自动成为正典。
- 已确认事实必须回写到对应 Markdown 条目，不能只存在图里。
- 只服务于某部作品的轻量附件放在该作品的 `10_attachments/`；跨作品或项目级附件才放 `06_attachments/`。
- 会被多个媒介复用的原始成品素材放 `assets/`，使用 `OAP-ASSET-####` 并在 `ASSET_REGISTER.md` 登记。
- 需要长期引用的外部来源使用 `OAP-SRC-####`。

## 6. 最小工作法

1. 不知道放哪里，放 `00_inbox/`。
2. 只属于一部作品的东西，留在这部作品内。
3. 只有已确认、并且跨作品成立的事实，才进入 `02_canon/`。
4. 每次停笔前留一句“下次从这里继续”。

## 边界

本文件不创造故事内容，不确认正典，也不替代根目录的 `PROJECT_MANUAL.md`。如有冲突，以用户最新决定、`DECISIONS.md` 和项目手册为准。
